# GNUCMS

GNUCMS는 일반 웹호스팅에 설치하여 사용하는 PHP 기반 커뮤니티·콘텐츠 관리 시스템입니다.
별도의 애플리케이션 서버 없이 게시판, 회원, 약관, 일반 문서와 사이트 운영 기능을 한곳에서 관리하실 수 있습니다.

## 주요 기능

- SQLite, MySQL/MariaDB 중 원하는 데이터베이스를 사용하실 수 있습니다.
- 게시판별 읽기·쓰기·댓글 권한, 분류, 공지, 비밀글과 첨부 파일을 설정하실 수 있습니다.
- 목록형, 갤러리형, 매거진형, 뉴스형 게시판 화면을 지원합니다.
- 이메일 회원가입과 로그인, 이메일 인증, 비밀번호 재설정을 지원합니다.
- Google, 네이버, 카카오 소셜 로그인을 연결하실 수 있습니다.
- 회원 프로필 이미지, 알림, 로그인 기록과 회원 탈퇴 기능을 제공합니다.
- 일반 문서와 이용약관·개인정보 처리방침을 작성하고 동의 기록을 관리하실 수 있습니다.
- 사이트맵, `robots.txt`, 사이트·문서·게시판 RSS를 자동으로 제공합니다.
- 글과 댓글의 등록 간격·10분 한도·하루 한도를 설정하여 도배를 방지할 수 있습니다.
- 사이트 소유 확인 태그, 애널리틱스 코드와 애드센스 코드를 관리 화면에서 등록하실 수 있습니다.
- DB·첨부·에디터 이미지·설정을 관리 화면이나 CLI에서 전체 백업하고 검증할 수 있습니다.
- 데이터베이스 구조를 자동으로 갱신하며, SQLite는 갱신 전에 자동으로 백업합니다.

## 설치 전 준비

PHP 8.2 이상이 필요하며 PHP 8.4 사용을 권장합니다.

서버에는 다음 PHP 확장이 필요합니다.

- `PDO`
- 사용할 데이터베이스에 맞는 `pdo_sqlite`, `pdo_mysql` 중 하나
- `mbstring`
- `fileinfo`
- `openssl`
- `phar` (TAR 백업 대체 형식)
- `zip` (선택, 있으면 ZIP 백업을 우선 사용)

사진 축소본을 만들려면 `gd` 확장도 설치해 주세요. Apache의 `mod_rewrite`를 사용할 수 있으면
`/index.php/...`가 아닌 깔끔한 주소를 사용하실 수 있습니다.

배포본에는 실행에 필요한 `vendor/`가 포함되어 있습니다. 서버에서 Composer를 실행하실 필요가 없으며,
`vendor/`를 제외하지 말고 함께 업로드해 주세요.

GitHub Releases에서 `gnucms-vX.Y.Z.zip` 배포본을 내려받으면 됩니다. 소스 코드 자동 압축본에는
`vendor/`가 없으므로 운영 서버 배포에는 별도로 첨부된 GNUCMS 배포본을 사용해 주세요.

## 폴더 배치

가장 안전한 구성은 웹 문서 루트가 프로젝트의 `www/` 폴더를 가리키도록 하는 것입니다.

```text
gnucms/
├── config/
├── src/
├── storage/
├── templates/
├── vendor/          웹에서 직접 접근할 수 없게 두세요.
└── www/             웹 문서 루트
    ├── .htaccess
    ├── index.php
    └── install.php
```

`storage/`, `config/`, `src/`, `templates/`, 루트의 `vendor/`는 웹에서 직접 내려받을 수 없는 위치에
두셔야 합니다. 특히 SQLite 데이터베이스와 설정 파일이 외부에 공개되지 않도록 주의해 주세요.

### 카페24 웹호스팅에 올리는 방법

카페24 계정의 `www/`가 웹 문서 루트라면 다음과 같이 올려 주세요.

1. 프로젝트의 `www/` 안에 있는 파일과 폴더를 호스팅 계정의 `www/` 안에 올려 주세요.
2. 프로젝트의 `config/`, `src/`, `storage/`, `templates/`, `vendor/`는 호스팅 계정의 `www/`와
   같은 단계에 올려 주세요.
3. 숨김 파일인 `www/.htaccess`가 빠지지 않았는지 확인해 주세요.
4. `config/`와 `storage/`에 PHP가 쓸 수 있는 권한을 부여해 주세요.

호스팅 상품마다 FTP 시작 위치가 다를 수 있습니다. 업로드 후 `www/index.php`에서 한 단계 위의
`vendor/autoload.php`를 찾을 수 있는 구조인지 확인해 주세요.

## 웹 설치

1. 파일 업로드를 마친 뒤 사이트 주소를 브라우저에서 열어 주세요.
2. 아직 설정 파일이 없으면 설치 화면으로 자동 이동합니다. 자동 이동하지 않으면
   `https://사이트주소/install.php`를 직접 열어 주세요.
3. 서버 점검에서 필수 항목이 모두 통과하는지 확인해 주세요.
4. 사용할 데이터베이스를 선택하고 접속 정보를 입력해 주세요.
5. 사이트 이름, 사이트 주소와 발신 이메일을 입력해 주세요.
6. 처음 사용할 관리자 계정을 만들어 주세요.
7. 마지막 확인 화면에서 설치를 실행해 주세요.

설치가 끝나면 `config/config.php`가 생성되고 데이터베이스 테이블이 만들어집니다. 설치 프로그램은
완료 후 `www/install.php`를 자동으로 삭제합니다. 자동 삭제에 실패했다는 메시지가 나오면 FTP에서
해당 파일을 직접 삭제해 주세요.

설정 파일이 만들어지기 전에는 다른 방문자도 설치 화면에 접근할 수 있으므로, 파일을 업로드한 뒤
바로 설치를 완료해 주세요.

## 데이터베이스 선택

| 데이터베이스 | 이런 경우에 권장합니다 |
|---|---|
| SQLite | 소규모 사이트를 가장 간단하게 설치하고 싶으실 때 적합합니다. 별도 DB 서버가 필요하지 않습니다. |
| MySQL/MariaDB | 카페24를 포함한 일반 웹호스팅에서 제공하는 DB를 사용하실 때 적합합니다. |

### SQLite

설치 화면에 웹 문서 루트 밖의 절대 경로를 입력해 주세요.

```text
/home/계정/gnucms/storage/board.sqlite
```

SQLite 파일이 없어도 설치 과정에서 생성됩니다. 파일이 들어갈 `storage/` 폴더에는 쓰기 권한이
있어야 합니다. 방문자와 글 작성이 많은 사이트라면 MySQL/MariaDB를 권장합니다.

### MySQL/MariaDB

호스팅 관리 화면에서 다음 정보를 확인한 뒤 설치 화면에 입력해 주세요.

- DB 호스트
- DB 포트(일반적으로 `3306`)
- DB 이름
- DB 사용자 이름
- DB 비밀번호

GNUCMS는 MySQL 연결에 `utf8mb4` 문자셋을 사용합니다. 한글과 이모지를 올바르게 저장하려면
데이터베이스도 `utf8mb4`로 만들어 주세요.

### 테이블 프리픽스

한 데이터베이스에 GNUCMS를 여러 개 설치하실 때만 `site1_`, `site2_`처럼 서로 다른 프리픽스를
사용해 주세요. 프리픽스는 영문으로 시작하고 영문·숫자·밑줄만 사용할 수 있으며 밑줄로 끝나야 합니다.
설치 후 프리픽스를 바꾸면 기존 테이블을 찾지 못하므로 변경하지 마세요.

## 설치 후 처음 할 일

설치할 때 만든 관리자 계정으로 `/login`에서 로그인해 주세요. 로그인 후 화면의 관리자 메뉴 또는
`/admin`으로 들어가시면 관리 콘솔을 사용하실 수 있습니다.

처음에는 다음 순서로 설정하시는 것이 편리합니다.

1. **사이트 설정 → 기본·홈**에서 사이트 이름, 소개, 홈 화면 문구와 회원가입 정책을 확인해 주세요.
2. **게시판 관리 → 새 게시판**에서 첫 게시판을 만들어 주세요.
3. **사이트 설정 → 회원·글쓰기**에서 비회원 작성, 글자 수, 도배 방지와 첨부 파일 제한을 정해 주세요.
4. 회원가입과 비밀번호 재설정을 사용하실 경우 **사이트 설정 → 메일**에서 SMTP를 연결해 주세요.
5. 소셜 로그인이 필요하면 **사이트 설정 → 소셜 로그인**에서 제공자별 키를 등록해 주세요.
6. **약관 관리**에서 이용약관과 개인정보 처리방침을 준비하고 필요한 동의 항목을 연결해 주세요.

## 게시판 사용

관리 콘솔의 **게시판 관리**에서 게시판을 만들거나 수정하실 수 있습니다.

- 게시판 키는 주소에 사용되므로 짧은 영문 소문자 이름을 권장합니다.
- 읽기, 글쓰기와 댓글 권한을 각각 설정하실 수 있습니다.
- 게시판을 상단 메뉴에 표시할지 선택하실 수 있습니다.
- 목록형, 갤러리형, 매거진형, 뉴스형 중 원하는 목록 화면을 선택하실 수 있습니다.
- 분류, 비밀글, 첨부 파일과 게시판별 공지 기능을 사용할 수 있습니다.
- 관리자는 특정 게시판의 글과 댓글만 관리할 게시판 관리자를 지정할 수 있습니다.

공개 화면에서는 전체 글 목록과 게시판별 목록을 제공하며, 글 작성자는 본인의 글과 댓글을 수정하거나
삭제할 수 있습니다. 비회원 글과 댓글은 작성할 때 입력한 비밀번호로 본인 여부를 확인합니다.

## 회원과 로그인 관리

**회원 관리**에서는 회원의 정보와 상태를 확인하고 일반 회원을 차단하거나 다시 활성화하실 수 있습니다.
회원은 자신의 계정 화면에서 표시 이름, 이메일, 비밀번호와 프로필 이미지를 관리할 수 있으며 회원 탈퇴도
진행할 수 있습니다.

**로그인 기록**에서는 다음 항목을 확인하실 수 있습니다.

- 로그인 성공·실패 여부
- 이메일 로그인 또는 소셜 로그인 방식
- 접속 IP와 브라우저 정보
- 로그인 시각

회원, IP 또는 검색어로 기록을 좁혀 볼 수 있으며, 지정한 날짜보다 오래된 기록을 삭제하실 수 있습니다.
각 회원도 자신의 계정 화면에서 최근 로그인 기록을 확인할 수 있습니다.

## 글·댓글 도배 방지

**사이트 설정 → 회원·글쓰기 → 도배 방지**에서 글과 댓글 제한을 각각 설정하실 수 있습니다.

- 다음 글 또는 댓글을 등록할 때까지 기다려야 하는 시간
- 10분 동안 등록할 수 있는 개수
- 하루 동안 등록할 수 있는 개수

회원은 계정별로, 비회원은 IP별로 제한합니다. 값이 `0`이면 해당 제한을 사용하지 않습니다. 전역 관리자는
공지 작성과 운영 작업에 방해받지 않도록 이 제한을 적용받지 않습니다.

### Cloudflare Turnstile

회원가입, 비밀번호 찾기·인증 메일 재발송과 비회원 글·댓글에 자동 등록 방지를 적용하려면
Cloudflare에서 Turnstile 위젯을 만든 뒤 **사이트 설정 → 보안**에서 Site Key와 Secret Key를 입력하고
사용을 켜세요. Secret Key는 `auth.secret`으로 암호화해 데이터베이스에 저장하며, 관리자만 설정 화면의
눈 버튼으로 확인할 수 있습니다. Cloudflare DNS나 CDN을 사용하지 않아도 Turnstile만 독립적으로 사용할 수 있습니다.

파일로 관리해야 하는 배포 환경에서는 아래 `config/config.php` 값을 fallback으로 쓸 수도 있습니다.
관리자 화면에서 한 번 저장한 항목은 파일 설정보다 우선합니다.

```php
'turnstile' => [
    'enabled' => true,
    'site_key' => '공개 사이트 키',
    'secret_key' => '서버 비밀 키',
    'hostname' => 'community.example.com',
],
```

정상 로그인에는 표시하지 않습니다. 같은 이메일과 IP에서 비밀번호를 세 번 틀린 뒤부터 Turnstile을
요구하고, Turnstile을 통과한 비밀번호 시도가 열 번 실패하면 10분 동안 잠급니다. Turnstile을 끄거나
키를 아직 설정하지 않은 사이트는 기존의 5회 로그인 실패 잠금을 그대로 사용합니다. `secret_key`는
브라우저나 공개 저장소에 노출하지 마세요.

## 메일 설정

회원 이메일 인증과 비밀번호 재설정 메일을 보내려면 **사이트 설정 → 메일**에서 SMTP를 설정해 주세요.
Gmail, 네이버 메일, 다음 메일은 기본 서버 정보를 선택할 수 있으며 다른 서비스는 직접 입력하실 수 있습니다.

일반 로그인 비밀번호 대신 메일 서비스에서 발급한 앱 비밀번호를 사용해 주세요. 설정을 저장한 뒤
**테스트 메일 보내기**로 실제 발송 여부를 확인하시는 것을 권장합니다. 저장된 SMTP 비밀번호는
`config/config.php`의 `auth.secret`을 이용해 암호화됩니다.

## 소셜 로그인

**사이트 설정 → 소셜 로그인**에서 Google, 네이버, 카카오를 각각 설정하실 수 있습니다. 관리 화면에
표시되는 콜백 주소를 해당 개발자 콘솔에 정확히 등록한 뒤 Client ID와 Client Secret을 입력해 주세요.

소셜 로그인 전체 허용 여부와 신규 소셜 회원가입 허용 여부는 **사이트 설정 → 기본·홈**에서 별도로
정할 수 있습니다. 제공자 설정과 사이트의 로그인 정책이 모두 활성화되어야 로그인 버튼이 표시됩니다.

## 내용과 약관 관리

**내용 관리**에서는 소개, 안내와 같은 일반 문서를 작성하실 수 있습니다. 문서를 메뉴에 표시하거나
공개 전 미리보기로 확인할 수 있으며, 삭제한 문서는 휴지통에서 복구하거나 영구 삭제할 수 있습니다.

**약관 관리**에서는 이용약관과 개인정보 처리방침을 별도로 관리합니다. 회원가입 등 필요한 화면에
필수·선택 동의를 연결할 수 있고, 회원이 동의한 문서 버전과 시각도 확인하실 수 있습니다.

## 검색 서비스·통계·광고 연결

**사이트 설정 → 기본·홈 → 외부 서비스 코드**에서 다음 코드를 등록하실 수 있습니다.

- 네이버 서치어드바이저나 Google Search Console의 사이트 소유 확인 태그
- Google Analytics 또는 네이버 애널리틱스 코드
- Google AdSense 사이트 연결 또는 자동 광고 코드

저장한 코드는 공개 사이트의 `<head>`에 출력됩니다. 관리자만 수정할 수 있지만, 입력한 스크립트가 모든
방문자의 브라우저에서 실행되므로 반드시 신뢰할 수 있는 서비스에서 받은 코드만 넣어 주세요.

GNUCMS는 다음 주소도 자동으로 제공합니다.

- `/sitemap.xml`
- `/robots.txt`
- `/rss.xml`
- `/content/rss.xml`
- `/boards/{게시판키}/rss.xml`

## 전체 백업과 복원

**사이트 설정 → 시스템·유지보수 → 전체 수동 백업**에서 현재 사이트의 전체 백업을 만들 수 있습니다.
관리 화면의 **ZIP 백업 만들기** 또는 **TAR 백업 만들기**에서 옮길 서버가 읽을 수 있는 형식을 선택합니다.
형식을 지정하지 않으면 `ZipArchive`가 있는 서버는 `.zip`을, 없으면 `.tar`를 사용하며, GNUCMS는 두 형식을
모두 검증·복원할 수 있습니다. 서버에 해당 PHP 확장이 없으면 그 형식의 생성 단추는 표시되지 않습니다.
파일명과 관리 화면의 시각은 **사이트 설정 → 일반 설정 → 시간대**를 기준으로 표시됩니다.
백업에는 다음 내용을 포함합니다.

- SQLite 스냅숏 또는 `mysqldump`로 만든 네이티브 DB 덤프
- 첨부 파일, 에디터 이미지와 회원 프로필 이미지
- `config/config.php` 설정 사본
- 설치 레지스트리에 등록된 확장 DB 테이블과 `storage/extensions/`의 영속 상태 (잠금·임시 파일 제외)
- 모든 포함 파일의 크기와 SHA-256 체크섬을 기록한 `manifest.json`

생성이 끝나면 ZIP/TAR 형식, 개별 파일 체크섬과 DB 파일 형식을 즉시 다시 검사합니다. 관리 화면의 **검증**
단추나 아래 CLI 명령으로 보관 중인 파일을 언제든 다시 확인할 수 있습니다. 설정 사본에는 DB 비밀번호와
`auth.secret` 같은 비밀값이 있으므로 백업 파일은 공개 폴더에 옮기지 말고 안전하게 보관하세요.

새 백업 형식은 v2이며 기존 v1 백업도 읽을 수 있습니다. 확장 PHP 패키지는 배포본에서 따로
재배치해야 합니다. 토큰 캐시와 외부 실행 허용값은 백업하지 않으며 SQLite 복원 시 발송 허용을
해제합니다. v1 복원에는 확장 상태가 없으므로 확장은 다시 활성화해야 합니다.
테이블 접두사가 있는 SQLite 백업도 검증·복원하며, 현재 설정과 접두사가 다르면 자동 복원을 거부합니다.

웹 실행 시간이 짧거나 데이터가 많으면 프로젝트 루트에서 CLI를 사용하세요. 다른 설정 파일을 쓰려면 모든
명령에 `--config=/절대경로/config.php`를 덧붙일 수 있습니다.

```bash
php bin/backup.php create
php bin/backup.php create --format=zip
php bin/backup.php create --format=tar
php bin/backup.php list
php bin/backup.php verify gnucms-sqlite-20260904-120000.zip
php bin/backup.php restore gnucms-sqlite-20260904-120000.zip --yes
php bin/backup.php delete gnucms-sqlite-20260904-120000.zip --yes
```

파일 이름만 쓰면 `storage/backups/manual/`에서 찾습니다. 내려받아 따로 보관하던 백업은 서버의 안전한
폴더에 다시 올린 뒤 CLI의 `verify`와 `restore`에 그 파일의 절대 경로를 지정할 수 있습니다. 관리 화면의
**내려받은 백업 가져오기**에서는 GNUCMS ZIP/TAR를 업로드하고 즉시 검증하여 복원 목록에 추가할 수 있습니다.
브라우저 다운로드 과정에서 `(1)` 등이 붙거나 다른 이름으로 바뀐 파일도 내부 정보를 기준으로 표준 이름에
저장합니다. 기존 백업과 시각이 같으면 `-2`, `-3`을 붙여 덮어쓰지 않습니다. 웹 업로드 한도보다 큰 파일은
SFTP 등으로 서버의 안전한 폴더에 올린 뒤 CLI를 사용하세요.
더 이상 필요하지 않은 백업은 관리 화면의 **삭제** 단추나 CLI `delete ... --yes`로 검증
기록과 함께 지울 수 있습니다. 수동 백업은 자동으로 지우지 않습니다.

SQLite 파일 DB는 관리 화면과 CLI에서 전체 복원할 수 있습니다. 복원할 파일을 다시 검증한 다음 현재 DB와
파일을 별도 전체 백업으로 먼저 보관하고, 준비한 DB·파일을 같은 파일시스템 안에서 교체합니다. 실행 중인
`config/config.php`는 자동으로 덮어쓰지 않습니다. 같은 설치를 되돌릴 때는 현재 설정을 유지하고, 다른
서버로 이전할 때는 아카이브의 설정 사본과 새 서버의 경로·접속 정보를 사람이 비교하여 적용하세요.
복원할 백업과 현재 설치의 테이블 프리픽스는 같아야 합니다.

MySQL/MariaDB 백업에는 서버의 `mysqldump`가 필요합니다. 웹 서버에서 외부 명령 실행이 꺼져 있거나
해당 도구가 없으면 관리 화면에 원인이 표시됩니다. MySQL/MariaDB의 자동 웹 복원은 지원하지 않습니다.
전체 백업을 내려받은 뒤 서비스 쓰기를 중지하고, 유지보수 화면에 표시된 `mysql` 명령으로 복원하세요.
DB 비밀번호는 명령 인자에 직접 넣지 말고 프롬프트 또는 MySQL 옵션 파일을 사용하세요.

**업로드 파일 정리**에는 어떤 글에도 연결되지 않은 채 24시간 넘게 남은 첨부 파일이 삭제 전에 표시됩니다.
저장 경로, 축소본을 포함한 파일 수·용량과 마지막 변경 시각을 확인한 다음 목록의 파일만 정리할 수 있습니다.
실행 시에는 대상을 다시 계산하므로 그 사이 글에 연결된 파일이나 새로 업로드한 파일은 삭제하지 않습니다.

## 업데이트

업데이트 전에는 관리 화면이나 `php bin/backup.php create`로 전체 백업을 만들고 검증해 주세요. 외부 DB
도구를 실행할 수 없는 호스팅이라면 관리 화면에 안내된 절차나 호스팅의 DB 백업 기능을 이용하세요.

1. 전체 수동 백업과 사용자 정의 템플릿을 별도로 보관해 주세요.
2. 새 배포본의 파일과 `vendor/`를 서버에 덮어써 주세요.
3. 사이트에 한 번 접속해 주세요.
4. **사이트 설정 → 시스템·유지보수**에서 데이터베이스 판 번호와 갱신 상태를 확인해 주세요.

첫 요청에서 데이터베이스 구조가 자동으로 갱신됩니다. SQLite는 갱신 전에 `storage/backups/`에 DB 전용
백업을 남기며 최근 백업 5개를 보관합니다. 이 자동 파일은 위의 전체 수동 백업과 별개이며,
시스템·유지보수 화면에서 개별 삭제할 수 있습니다.

갱신에 실패하면 방문자에게 503 점검 화면이 표시되고 원인은 `storage/logs/error.log`에 기록됩니다.

## 문제 해결

### 설치 화면이 열리지 않습니다

- `www/install.php`가 업로드되어 있는지 확인해 주세요.
- 루트 `vendor/`가 함께 업로드되어 있는지 확인해 주세요.
- PHP 버전과 필수 확장을 호스팅 관리 화면에서 확인해 주세요.

### 주소를 열면 404 오류가 납니다

- `www/.htaccess`가 누락되지 않았는지 확인해 주세요.
- Apache에서 `mod_rewrite`를 사용할 수 있는지 확인해 주세요.
- rewrite를 사용할 수 없다면 `/index.php/boards/...` 형식의 주소를 사용해 주세요.

### 파일이나 설정을 저장하지 못합니다

`config/`와 `storage/` 및 그 하위 폴더에 PHP 프로세스가 쓸 수 있는지 확인해 주세요. 필요 이상으로
넓은 권한을 주기보다는 호스팅에서 권장하는 소유자와 권한 설정을 사용해 주세요.

### 첨부 파일이 서버 설정값보다 크게 올라가지 않습니다

관리 화면의 첨부 용량뿐 아니라 PHP의 `upload_max_filesize`와 `post_max_size`도 함께 적용됩니다.
두 값이 GNUCMS 설정보다 작으면 호스팅의 PHP 설정을 먼저 조정해 주세요.

### 오류 원인을 확인하고 싶습니다

운영 중 오류는 기본적으로 `storage/logs/error.log`에 기록됩니다. 운영 사이트에서는
`config/config.php`의 `debug`를 `false`로 유지해 주세요.

## 작은 쇼핑몰과 결제

1인 운영 쇼핑몰 모듈과 **PG 상점 코드를 사용하는 직접 결제 연동**을 제공한다. 이니시스·토스페이먼츠 어댑터를 연결하며 KCP·KSPay는 미확인 규격으로 결제 실행을 제한한 준비 단계다. 상품 옵션은 두 종류까지이며 조합별 재고, 회원 주문, 배송·반품·환불·교환, 수량·금액 정산을 관리한다. 결제는 원화 일반 과세 카드결제를 사용하며 토스페이먼츠 통합결제창의 간편결제도 지원한다.

[쇼핑몰 설치·운영 안내](docs/shop.md)에서 외부 계정 준비, 테스트·운영 전환, 오류 복구와 정산 기준을 확인할 수 있다.
