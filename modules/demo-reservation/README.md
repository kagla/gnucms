# 예약 안내문 모듈 데모

독립적으로 동작하면서 선택 플러그인의 기능을 조합하는 프로그램 예제다.
이름·날짜·시간·인원을 검증한 뒤 예약 안내문을 미리 보여준다.
**실제 예약 생성·중복 예약 검사·DB 저장·발송·주기적 실행은 포함하지 않는다.**
데모는 실제 가용 시간을 판단하지 않으므로 과거 날짜도 미리보기 입력으로 허용한다.

## 실행

1. GNUCMS 전체 관리자로 로그인한다.
2. **모듈** 메뉴에서 **데모 · 예약 안내문** 토글을 켜고 목록 위·아래의 **저장**을 누른다.
3. 목록의 **바로가기** 또는 실행 주소 링크(`/extensions/modules/demo-reservation/preview`)를 누른다.
4. 이름·날짜·시간·인원을 입력하고 **안내문 생성**을 누른다.

사이트가 `/cms`에 설치되어 있으면 주소 앞에 `/cms`를 붙인다.
메시지 플러그인을 설치하거나 켜지 않아도 동작한다.

### 사용 설정 없이 관리자 테스트

모듈이 미사용 상태일 때 목록의 **관리자 테스트**를 누른다.
테스트 주소는 `/admin/modules/demo-reservation/test`이며, 이름·날짜·시간·인원을 입력하고
안내문을 생성할 수 있다. 사용 설정과 최근 변경 순서는 바뀌지 않는다.
일반 실행 주소는 계속 404이고 비회원·일반회원은 테스트 주소에 접근할 수 없다.
테스트의 POST 폼에도 CSRF 검사가 적용된다. 활성화된 메시지 플러그인이 있으면 연동한다.

`extension.json`의 `entry_path: "/preview"`가 실제 실행 경로를 선언하며,
`admin_test: true`가 이 관리자 테스트를 허용한다. 다른 패키지는 기본적으로 테스트가 꺼져 있다.
테스트 요청에는 `Context::TEST_ATTRIBUTE` 속성이 `true`로 전달된다.
컨트롤러는 이를 확인해 폼이 테스트 주소에 다시 제출되도록 하고 화면에 테스트 상태를 표시한다.

## 독립 실행과 연동 비교

| 상태 | 동작 |
| --- | --- |
| 모듈 OFF | 일반 실행 주소가 404, 전체 관리자는 별도 관리자 테스트 가능 |
| 모듈 ON, 메시지 플러그인 없음/OFF | 기본 안내문 생성, 화면에 독립 실행 표시 |
| 모듈 ON, 메시지 플러그인 ON | `[데모 알림 · 예약 안내]` 형식 적용, 연결 상태 표시 |
| 메시지 플러그인을 다시 OFF | 모듈을 유지하면서 다음 요청부터 기본 안내문으로 복귀 |

연동하려면 **플러그인** 메뉴에서 **데모 · 메시지 형식**을 켠 뒤 이 화면을 새로고침한다.
모듈의 `optional` 선언 덕분에 활성 플러그인의 서비스가 먼저 등록된다.

## 파일별 역할

| 파일 | 역할 |
| --- | --- |
| `extension.json` | 모듈 ID와 선택 플러그인 선언 |
| `bootstrap.php` | 선택 서비스 조회·주입과 관리자 GET/POST 등록 |
| `src/ReservationPreview.php` | 입력 검증, 기본 안내문 생성, 선택 서비스 호출 |
| `src/PreviewController.php` | HTTP 입력과 422 오류 처리, 화면 렌더링 |
| `templates/preview.php` | 폼, 연결 상태, 결과 출력 |
| `templates/_style.php` | 패키지 자체 화면 스타일 |

이 예제에는 영속 데이터가 없어 저장소 클래스와 마이그레이션이 없다.
두 패키지의 간단한 화면 렌더링과 스타일은 각각 소유하도록 유지했다.
따라서 플러그인 폴더를 제거해도 모듈의 PHP·템플릿 로딩이 실패하지 않는다.

## 개발 시 참고할 부분

- `ReservationPreview`는 `?Closure`를 주입받으며 플러그인의 클래스를 직접 참조하지 않는다.
- 서비스가 없으면 기본 문구를 만들고, 있으면 `Closure(string, string): string` 계약으로 호출한다.
- 이름은 한 줄·최대 60자, 날짜는 실제 달력 날짜, 시간은 `00:00`~`23:59`, 인원은 정수 1~20명을 검사한다.
- 브라우저의 `required`, `min`, `max`와 별개로 서버에서 다시 검증한다.
- GET/POST 모두 전체 관리자 전용이다. POST의 CSRF 검사는 공통 확장 기반이 처리한다.
- 오류 시 422와 입력 폼을 반환하고, 입력·오류·결과는 `$this->e()`로 출력한다.
- 응답은 `Cache-Control: no-store`로 제공한다. 입력 데이터는 파일·DB·세션에 저장하지 않는다.
- 경로를 만들 때 `RouteContext`의 기준 경로를 사용해 하위 디렉터리 설치도 지원한다.
- 코어·기본 테마·Composer 설정 변경 없이 패키지 파일 배포와 토글만으로 동작한다.

새 모듈로 복사할 때는 폴더명·설명 파일 ID·PHP 네임스페이스·컨트롤러의 `form_url`을 변경한다.
필수 기능이라면 `optional` 대신 `requires`에 선언한다. 이 경우 플러그인을 먼저 켜야 한다.
실제 예약을 구현할 때는 저장소·동시 예약 방지·DB 마이그레이션·취소 정책을 별도로 설계한다.
쓰기 경로는 `storage/` 아래에서 패키지별로 구분하고 업무 기한은 요청 시에도 검증한다.

회귀 테스트: `./vendor/bin/phpunit tests/Web/DemoExtensionsTest.php`
