# CMS 개발 우선순위 제안

이 문서는 GNUCMS의 현재 기능을 기준으로, 기본 CMS로서 추가할 기능과 권장 개발 순서를 정리한
계획 자료다. 확정된 릴리스 일정이나 구현 완료 목록은 아니며, 제품 방향과 운영 경험에 따라 순서를
조정할 수 있다.

우선순위는 다음 기준으로 정했다.

1. 데이터 손실과 보안 사고를 예방하는가
2. 장기간 운영하거나 여러 관리자가 협업할 때 필요한가
3. 일반적인 사이트에서 자주 사용하는가
4. 기존 구조를 크게 확장하지 않고 단계적으로 제공할 수 있는가

## 권장 개발 순서

### 1. 수동 백업·복원·내보내기

현재 SQLite 백업은 데이터 구조를 갱신하기 직전에만 자동 생성되며, MySQL/MariaDB는
외부 DB 도구에 의존한다. 운영자가 관리 화면이나 CLI에서 직접 전체 백업을 만들고 검증할 수 있는
기능을 우선 추가한다.

- DB, 첨부 파일, 에디터 이미지와 필요한 설정을 함께 내보낸다.
- 관리 화면에서 수동 백업을 만들고 내려받을 수 있게 한다.
- 백업 파일의 형식과 무결성을 검사한다.
- 복원 전 현재 데이터를 다시 백업한다.
- 웹 실행 시간이 부족한 환경을 위해 CLI 명령도 함께 제공한다.
- MySQL/MariaDB의 안전한 웹 복원이 어렵다면 내보내기와 복원 절차 안내부터 제공한다.

### 2. 관리자 작업 감사 로그

로그인 기록과 별도로 관리자가 시스템에 가한 변경을 기록한다.

- 회원 차단, 관리자·역할 변경
- 게시판 생성·삭제와 권한 변경
- 글·댓글 강제 삭제와 복원
- 사이트, OAuth, SMTP와 보안 설정 변경
- 백업·복원 실행
- 수행자, 대상, IP, 실행 시각과 필요한 범위의 변경 전후 값

비밀번호, SMTP 비밀번호, OAuth 비밀키, Turnstile 비밀키 등의 원문은 감사 로그에 저장하지 않는다.

### 3. 역할 기반 관리자 권한

현재의 전역 관리자와 게시판 관리자 구분을 확장해 관리 업무를 안전하게 위임할 수 있게 한다. 처음부터
자유로운 권한 조합을 제공하기보다 다음과 같은 고정 역할로 시작한다.

- 최고 관리자: 설정, 관리자 지정, 백업과 복원
- 사이트 관리자: 콘텐츠, 회원과 게시판 관리
- 편집자: 문서와 게시물 관리
- 게시판 관리자: 지정된 게시판의 글과 댓글 관리

관리자 권한 변경도 감사 로그에 반드시 남긴다.

### 4. 콘텐츠 수정 이력과 되돌리기

문서를 저장할 때 이전 내용을 보존해 실수나 잘못된 편집에서 복구할 수 있게 한다.

- 저장할 때마다 문서 revision을 생성한다.
- 작성자와 저장 시각을 표시한다.
- 버전 간 제목과 본문 차이를 확인할 수 있게 한다.
- 선택한 버전으로 되돌릴 수 있게 한다.
- 보관 개수나 기간을 제한해 데이터가 무한히 늘지 않게 한다.

### 5. 메뉴·내비게이션 관리

문서나 게시판의 단순 노출 설정과 별도로 사이트 메뉴를 관리한다.

- 문서, 게시판과 외부 URL을 메뉴 항목으로 연결한다.
- 항목의 표시 순서를 관리한다.
- 한두 단계의 하위 메뉴를 지원한다.
- 헤더와 푸터 메뉴를 구분한다.
- 비공개 문서나 접근할 수 없는 게시판은 자동으로 제외한다.

초기 구현은 드래그 앤 드롭 없이 순서 숫자와 상위 항목 선택 방식으로 제공해도 된다.

### 6. 통합 미디어 라이브러리

글과 문서에 종속된 업로드를 한곳에서 찾고 안전하게 재사용할 수 있게 한다.

- 이미지와 파일 목록, 검색과 재사용
- 사용 중·미사용 상태와 참조 위치 확인
- 제목, 대체 텍스트와 설명 관리
- 참조 검사 후 안전한 삭제
- 저장 공간과 파일 종류별 사용량 표시

이미지 접근성을 위해 대체 텍스트 입력과 출력도 같은 작업에서 다룬다.

### 7. 글·문서 예약 공개와 공개 종료

공개 시작 시각과 종료 시각을 지정할 수 있게 한다.

- 초안, 예약, 공개와 종료 상태를 구분한다.
- 사이트 시간대를 설정하고 일관되게 표시한다.
- cron을 사용할 수 없는 일반 웹호스팅에서도 요청 시각을 기준으로 공개 여부가 올바르게 계산되게 한다.
- cron을 사용할 수 있는 환경에서는 선택적으로 예약 작업을 지원한다.

### 8. 신고·차단·검수 관리

등록 속도 제한과 Turnstile 이후의 운영 단계에서 필요한 관리 기능을 추가한다.

- 게시글과 댓글 신고, 신고 사유와 처리 상태
- IP, 이메일과 금칙어 차단
- 신고된 콘텐츠의 일괄 숨김·삭제
- 신규 회원의 첫 글 승인 옵션
- 휴지통 자동 정리 기간

공개 가입형 커뮤니티를 우선 목표로 한다면 이 항목은 메뉴나 미디어 관리보다 먼저 개발할 수 있다.

### 9. URL 변경 이력과 리디렉션

문서 slug나 게시판 키를 바꾸더라도 기존 링크와 검색 결과가 깨지지 않게 한다.

- 주소 변경 시 이전 URL을 기록한다.
- 이전 주소에서 새 주소로 301 응답을 보낸다.
- 관리 화면에서 리디렉션을 확인하고 관리한다.
- 순환 리디렉션과 중복 주소를 방지한다.
- 삭제된 콘텐츠의 URL 처리 정책을 정한다.

### 10. 관리자 대시보드와 시스템 상태 확장

현재의 콘텐츠 개수와 바로가기 중심 대시보드를 운영 상태 확인 화면으로 확장한다.

- 최근 가입, 글과 댓글
- 처리하지 않은 신고
- 실패 로그인 급증
- 디스크와 업로드 저장 공간 사용량
- 메일과 쓰기 가능 디렉터리 상태
- 마지막 백업 시각과 오래된 백업 경고
- PHP, DB와 필수 확장 상태

## 이후 검토할 기능

위 기능이 안정된 뒤 다음 항목을 검토한다.

1. 문서 계층 구조와 빵부스러기 경로
2. 콘텐츠와 회원 CSV 가져오기·내보내기
3. 이메일 알림 구독과 회원별 알림 설정
4. 문서와 게시글을 함께 찾는 사이트 전체 검색
5. 관리자 2단계 인증과 복구 코드
6. 웹훅 또는 읽기 전용 API
7. 다국어 콘텐츠
8. 확장 모듈·플러그인 체계

API, 다국어, 플러그인 마켓, 페이지 빌더와 전자상거래는 기본 CMS의 안전한 운영 범위를 넘어 제품
방향을 크게 확장하므로, 위의 운영 필수 기능보다 먼저 개발하지 않는다.

## 권장 첫 개발 묶음

첫 번째 개발 묶음은 다음 네 가지로 한다.

1. 수동 백업·복원·내보내기
2. 관리자 작업 감사 로그
3. 역할 기반 관리자 권한
4. 콘텐츠 수정 이력과 되돌리기

이 묶음은 콘텐츠를 안전하게 보존하고 여러 운영자가 책임 있게 관리할 수 있는 기반을 만드는 데
초점을 둔다.
