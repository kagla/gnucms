# 쇼핑몰 운영 안내

영카트5의 기능을 GNUCMS 코어 기능으로 다시 만든 쇼핑몰이다. 게시판·회원처럼 처음부터 있으며
별도 모듈 설치는 필요 없다. 상점 설정의 쇼핑몰 공개 스위치는 있으며 끄더라도 관리자와 기존 데이터는 유지된다. 분류·상품·옵션·이미지·재고 관리와
반응형 종합 쇼핑몰 화면, 장바구니, 회원 주문 접수·조회·취소, 관리자 주문 처리를 제공한다.
온라인 결제는 코어 결제 계층(설정 → 결제, `docs/payments.md`)에서 KG이니시스·NHN KCP 기존 TCP/IP 방식·토스페이먼츠·나이스페이먼츠 중 하나를 골라 일반 신용카드로 처리한다. 카드 결제를
끄면 무통장입금을 사용하거나 접수만 받고 판매자가 결제를 따로 안내할 수 있다.

## 주소와 패키지

| 항목 | 값 |
|---|---|
| 코드 | `src/Shop` (`GnuCms\Shop`), 템플릿 `templates/default/shop/`, 테마 덮어쓰기 `templates/<테마>/shop/` |
| 사용자 주소 | `/shop` — 메인 `/shop`, 분류 `/shop/c/슬러그`(옛 `/shop/list?ca=코드`는 새 주소로 넘긴다), 유형 `/shop/type?t=new|best|popular|discount`(옛 `hit`·`recommend`는 옮겨진 분류로 넘긴다), 검색 `/shop/search?q=`, 상세 `/shop/item?id=상품코드` 또는 `?slug=`, 후기·문의 작성 `/shop/item/feedback`, 이미지 `/shop/image`, 장바구니 `/shop/cart`, 주문서 `/shop/checkout`, 주문 조회 `/shop/orders`, 주문 상세 `/shop/order?ref=주문번호-서명`, 이전 결제 대기 주문용 `/shop/pay?ref=주문번호-서명`, 결제 콜백 `/shop/pay/callback`(이니시스가 부른다, 세션 없음) |
| 관리자 주소 | `/admin/shop` 현황, `/admin/shop/settings`, `/admin/shop/categories`, `/admin/shop/products`와 `new`·`edit`·`stock`·`option-stock`·`settings-copy`, 상품 소메뉴의 후기·문의 `/admin/shop/feedback`, 주문 목록 `/admin/shop/orders`, 주문 상세 `/admin/shop/orders/detail?id=번호` |
| 테이블 | `yc_settings`, `yc_categories`, `yc_products`, `yc_product_categories`, `yc_product_images`, `yc_option_groups`, `yc_options`, `yc_stock_log`, `yc_orders`, `yc_order_items`, `yc_order_history`, `yc_order_notes`, `yc_product_feedback` |

`/shop`은 코어 주소다. 같은 기본 주소를 선언한 모듈은 실행되지 않는다.

## 설치와 업그레이드

설치할 것이 없다. 코어 스키마가 표를 만들고, 관리자 메뉴의 **쇼핑몰**(`/admin/shop`)이 바로 열린다.
모듈(`modules/youngcart`) 시절에 설치한 사이트는 업그레이드 때 코어 스키마 27판이 그 표를 그대로
넘겨받고 확장 스키마 기록을 지운다. 확장 상태 파일에 남은 `modules/youngcart`는 무시되고 다음
저장 때 빠진다. 업로드(`uploads/youngcart/`)와 설정(`yc_settings`)은 그대로다.
31판은 상품의 진열 깃발을 없애고 히트·추천·인기 상품을 숨김 분류로 옮긴다 — 무엇이 어디로 가는지는
아래 **자동 묶음과 메인 블록** 절에 적어 두었다.
34판은 새 주문을 회원 전용으로 바꾸고 비회원 조회 비밀번호 컬럼을 제거한다. 새 설치는 `yc_orders.user_id`가 필수다.
기존 설치에 비회원 주문이 남아 있으면 이를 보존하기 위해 `user_id`의 NULL 허용 구조만 유지하며 새 비회원 주문은 받지 않는다.
40판은 관련상품 기능을 제거한다. 업그레이드할 때 기존 관련상품 관계 테이블과 설정 값도 삭제한다.
41판은 단일 판매자 운영에 맞춰 상품별 판매자 메일과 상세 화면 위·아래 HTML을 제거한다. 업그레이드할 때 기존 값도 삭제한다.
45판은 주문별 과세금액·공급가액·부가세·면세금액과 주문 상품별 면세 여부를 저장한다. 이전 주문에는
당시 면세 정보가 없으므로 전체 결제금액을 과세로 이전한다.
46판은 실제 신청·발송 기능 없이 남아 있던 상품의 재입고 알림 설정과 DB 컬럼을 제거한다.
47판은 상품정보고시와 중복되는 제조사·원산지·브랜드·모델 기본 필드와 기존 값을 제거한다.

판매를 하지 않는 사이트는 쇼핑몰 설정의 **쇼핑몰 공개**를 끈다. 상단 메뉴의 탭이 사라지고
`/shop` 화면은 "준비 중" 안내를 보인다. 관리자 화면과 그 화면이 끼워 넣는 이미지
(`/shop/image`·`/shop/banner-image`, 관리자만 조회할 수 있다), 이미 받은 주문의 영수증
(`/shop/order?ref=…`), 진행 중인 결제(`/shop/pay`와 `/shop/pay/callback`)는 영향을 받지 않는다.

주문번호는 영수증과 관리자 화면에 그대로 표시한다. 고객용 상세·결제 링크는 각 주문의 난수로 만든
128비트 서명을 붙이고, 서버에서 회원 소유권과 서명을 모두 확인한다. 기존 `?number=` 북마크는
본인 주문일 때만 새 링크로 이동한다. 주문 링크가 외부로 전송되지 않도록 응답에 `no-referrer`를 적용한다.

## 결제

주문서는 켜진 결제 수단만 보여 준다. 카드 결제는 쇼핑몰 설정에서 PG와 **결제 환경**(운영·테스트)을
고르고 해당 PG의 설정을 저장했을 때 나타난다. PG 계약에서 지원하지 않는 방식은 사용할 수 없다.
무통장입금은 쇼핑몰 설정에 계좌를 적고 켜면 나타난다.
PG 주문은 승인 전 주문서 내용을 암호화 원장에 임시 보관하고 승인·조회 성공 뒤 주문과 재고를 확정한다.
상품의 **면세 상품** 표시를 주문 상품에 그대로 저장하고, 한 주문에 과세·면세 상품이 섞이면
상품 금액을 과세 공급가액·부가세·면세 금액으로 나눠 결제사에 전달한다. 선불 배송비는 과세 금액에
포함한다. 결제사별 필드 변환과 부분 취소 세금 명세는 공통 `GnuCms\Payment\TaxAdapter`가 담당한다.

| 수단 | 흐름 |
|---|---|
| 신용카드 | 주문서에서 선택한 PG의 결제창 열기 → 콜백 승인·조회 → 주문·재고 확정 → **주문 접수 화면(결제 완료)** |
| 무통장입금 | 접수 → 주문 화면이 계좌·입금자명·기한을 안내 → 관리자가 주문 상세에서 **입금 확인** → **결제 완료** |

결제창을 닫거나 승인이 실패하면 주문·재고·장바구니는 그대로다. 승인 직후 재고·가격 등이
바뀌어 접수할 수 없다면 전액 취소를 요청한다. 취소 결과도 불확실하면 암호화 원장에 확인 필요
상태를 남기고 로그에 결제 원장 키를 기록한다. 예전에 접수된 PG 결제 대기 주문은 `/shop/pay`에서
계속 결제할 수 있다.

PG가 명시적으로 거절했거나 승인·주문 접수 결과를 확인할 수 없는 결제는 쇼핑몰 관리자 → 주문 →
**결제 오류**에서 참조번호·응답 코드로 검색할 수 있다. 기존 암호화 원장은 목록에 필요한 항목만
나눠 인덱싱하고, 결과 메시지는 화면에 표시할 때 해당 페이지 분량만 복호화한다. 승인은 완료됐지만
주문이 접수되지 않은 결제는 이 화면에서 PG 기록과 대조한다.

주문 상태 흐름: 주문 접수 → 결제 완료 → 상품 준비 → 배송 중 → 배송 완료, 그리고 취소. 결제
완료는 결제 확인으로만 들어가며 상태 변경 셀렉트에는 없다. 고객은 상품 준비 전의 주문 접수·결제 완료 상태에서 전체 주문을 취소할 수 있다.
결제 완료된 카드 주문은 결제사 전액 취소가 확인된 뒤 주문 취소와 재고 복원이 진행된다. 무통장입금은 주문을 취소하고 실제 입금액 반환은 상점에서 별도로 처리·기록한다.
관리자가 결제된 카드 주문을 취소하려면 먼저 **환불**(지원 PG는 부분 가능, 결제사 요청 뒤 기록)해야 한다.
무통장입금과 접수 전용 주문은 돈을 직접 돌려준 뒤 그 금액을 여기 기록만 한다(결제사를 부르지
않는다). 환불 폼의 "전액 환불이면 주문도 취소"가 켜져 있으면 전액 환불과 함께 취소되고 재고가
돌아간다.

환불을 요청했는데 결제사 응답을 받지 못하면 그 요청은 결제 원장에 보류로 남고 자동으로 다시
보내지 않는다 — 같은 돈이 두 번 빠져나가지 않게 하기 위해서다. 주문 상세의 결제 구역이 그 요청을
금액·사유·요청 시각과 함께 보여 준다. 결제사 관리자 화면에서 취소 내역을 확인한 뒤 **환불 대조**에
그 취소 거래번호를 넣으면 조회로 같은 금액인지 확인하고 주문에 환불로 기록한다. 결제사가 아예
처리하지 않았다면(요청 2시간 경과 후) **결제사 미처리로 정리**로 요청만 닫는다. 주문 금액은
그대로이고, 같은 환불 요청 키는 어느 경로로 들어와도 한 번만 계산된다.

결제 기한(쇼핑몰 설정, 카드 1시간, 무통장 72시간 기본)이 지난 미결제 주문은 관리자 주문 화면과
주문서(접수 직전)를 열 때 자동으로 취소되고 재고가 돌아간다. cron 은 없다. PG 승인이
진행 중이거나 끝난 주문은 만료로 취소하지 않는다 — 관리자의 **결제 상태 갱신**이 원장과 주문을
맞춘 뒤 처리한다.

결제창은 사이트 주소(`app.url`)가 공개 HTTPS 여야 열린다. 콜백 주소에는 주문의 결제 원장 키와
그 주문·결제사·설정 판의 HMAC 이 실려 있어, 다른 주문의 콜백으로는 승인되지 않는다. 카드번호와
PG 응답 원문은 저장하지 않으며 주문에는 거래번호와 표시용 정보만 남는다.

## 분류

- 관리자로 로그인하면 분류 목록 상단의 분류 경로 오른쪽에 **분류 관리** 링크가 표시되며 현재 분류의 수정 화면으로 이동한다.
- 분류는 상위 분류를 골라 만드는 트리다. 단계 제한은 없고 화면과 저장은 10단계까지 받는다. 수정 화면에서
  상위 분류를 바꾸면 자기와 하위 전체가 함께 옮겨진다. 자기 하위 분류 아래로는 옮길 수 없다.
- 주소는 슬러그다(`/shop/c/셔츠`). 슬러그는 상품과 같은 규칙으로 이름에서 만들고(한글 그대로, 공백은 `-`),
  직접 정할 수도 있으며 전체에서 하나여야 한다. 이름이 같은 분류는 `-2`, `-3`이 붙는다. 슬러그를 바꾸면 주소가
  바뀌므로 옛 주소는 더 이상 열리지 않는다.
- 수정 화면에서 **슬러그** 칸을 비우고 저장하면 이름에서 다시 만든다. 이름을 고치면서 이 칸을 비워 두면
  공개 주소도 함께 바뀌므로, 주소를 그대로 두려면 쓰던 슬러그를 남겨 둔다.
- 29판 이전에 쓰던 2자 코드는 `legacy_code`로 남아 옛 링크 `/shop/list?ca=코드`를 새 주소로 넘기는 데만 쓴다.
- 목록은 그 분류와 모든 활성 하위 분류의 상품을 보여 준다. 상품의 대표 분류와 추가 분류(최대 20개)
  어느 쪽에 연결되어도 나온다.
- 판매가능을 끄면 목록·검색·상세에서 숨겨진다. 관리자는 상세를 미리보기로 열 수 있다.
- 수정 화면의 **메뉴에서 숨김**은 이벤트·기획전 분류를 위한 것이다. 켜면 상단 메뉴, 메인 바로가기, 상위 분류
  화면의 하위 분류 칩에서 빠진다. 주소 `/shop/c/슬러그`, 빵부스러기, 검색, 배너·본문에 직접 건 링크는 그대로
  동작하므로 링크를 아는 사람만 들어온다. 상품은 관리자 상품 목록에서 체크해 **분류에 넣기**로 모으면 된다.
  판매가능과 달리 상품 노출을 막지 않으며, 하위 분류에 적용되지도 않는다(분류마다 따로 켠다). 메뉴 숨김
  분류는 아래 자동 묶음의 "기준: 분류 선택"이나 메인 분류 블록에도 그대로 쓸 수 있다 — 손으로 고른 목록이나
  기획전을 링크 없이도 메인에 올리는 방법이다.
- 하위 분류나 연결된 상품이 있으면 삭제할 수 없다.
- 수정 화면의 **하위 분류에 적용**은 판매·쿠폰·목록 크기·이미지 크기를 하위 분류에 함께 반영한다.
- **목록 위·아래 HTML**은 코어 편집기로 쓴다. 사진 올리기로 올린 사진은 분류의 폴더
  `/media/editor/categories/<분류 id>/`에 들어간다(첫 저장 전에는 `tmp/…`에 모였다가 저장하면서 옮겨지고
  본문 주소도 바뀐다). 저장할 때 본문에 없는 사진은 지워지고 분류를 지우면 폴더째 사라진다. 저장 위치와
  용량 제한은 내용 관리 편집기와 같다(`editor.dir`, `editor.max_bytes`).

## 상품

- 상세 설명의 편집기 사진은 상품의 폴더 `/media/editor/products/<상품 id>/`에 들어간다(첫 저장 전에는 `tmp/…`에
  모였다가 저장하면서 옮겨지고 본문 주소도 바뀐다). 저장할 때 본문에 없는 사진은 지워지고 상품을 지우면 폴더째
  사라진다. 이 방식 전에 올린 사진은 예전 32자 키 폴더에 그대로 남아 주소가 계속 동작한다.
- 관리자로 로그인하면 상품 상세 상단의 분류 경로 오른쪽에 **상품 관리** 링크가 표시되며 해당 상품의 수정 화면으로 이동한다.
- 관리자 상품 목록의 **분류** 거르개는 `의류 > 셔츠`처럼 전체 경로를 보여 주고 분류 id로 거르며, 고른 분류의
  하위 분류에 있는 상품까지 함께 보여 준다. 분류가 아닌 값이 들어오면 거르지 않는다(옛 코드가 든 북마크).
- 코드는 영문·숫자·`-`·`_` 1~20자이며 생성 후 바꿀 수 없다. 폼은 현재 시각 10자리를 제안한다.
- 판매가격이 표시 가격이다. 시중가격은 0이 아닐 때만 취소선으로 보인다. 전화문의를 켜면 가격 대신
  문구를 보여 주고 구매 UI를 숨긴다.
- 배송비 유형은 상점 기본·무료·조건부 무료·유료·수량별이다. 장바구니와 주문서에서 실제 금액을 계산한다.
- 상품 상세에는 상품정보·사용후기·상품문의·배송/교환 영역과 스크롤을 따라오며 각 영역으로 이동하는 앵커 메뉴가 있다. 배송/교환은 상점 설정의 안내 문구를 표시한다.
  결제 완료된 주문의 회원은 상품별로 후기를 한 번 작성할 수 있고, 로그인 회원은 공개 또는 비공개 문의를 남길 수 있다.
  비공개 문의 내용과 답변은 작성자·관리자에게만 보인다. 관리자는 `/admin/shop/feedback`에서 문의에 답변하거나
  후기·문의를 삭제한다. 후기가 추가·삭제되면 상품의 후기 건수와 평균 평점이 갱신된다.
- 재고 규칙은 하나다(`Shop\Catalog\Stock`): 주문 줄에 옵션(선택·추가)이 있으면 그 옵션 행의 재고, 없으면 상품 행의 재고를 쓴다.
  선택옵션 조합이 있는 상품의 상품 재고 칸은 쓰이지 않으므로 폼에서 잠긴다. 재고와 통보 기준은 상품 목록에서 수정하지 않고,
  상품 재고와 옵션 재고 화면에서 각각 관리한다. 재고 부족 알림도 옵션 상품은 조합 쪽에서만 본다.
- 품절은 수동 품절 표시이거나, 선택옵션이 있으면 사용 중인 조합의 재고가 모두 0일 때, 없으면 상품 재고가 0일 때다.
- 두 관리자가 같은 상품을 동시에 수정하면 나중 저장이 "다른 관리자가 먼저 저장했습니다" 오류로 거절된다.
  새로고침 후 다시 입력한다.
- 분류는 대표 분류 하나가 필수이고, 그 아래 **추가 분류**를 최대 20개까지 붙일 수 있다.
  **분류 추가**로 줄을 늘리고 **제거**로 지운다. 빈 줄, 대표 분류와 겹치는 줄, 같은 분류를 두 번 고른 줄은
  조용히 빠지고, 없는 분류나 20개 초과는 저장을 거절한다. 고른 순서가 그대로 진열 순서(slot 2 이상)가 된다.
- 상품 목록에서 상품을 체크하고 분류를 고른 뒤 **분류에 넣기**·**분류에서 빼기**를 누르면 선택한 상품의 추가
  분류를 한 번에 손본다. 넣기는 이미 그 분류에 있는 상품을 건너뛰고, 빼기는 대표 분류(slot 1)를 건드리지 않는다.
  결과는 "n개 상품을 분류에 넣었습니다"처럼 바뀐 수와 건너뛴 수로 안내한다.
- 상품 수정 화면에서 **설정 복사**를 누르면 현재 상품의 설정 복사 화면을 연다. 화면에서는 대상 상품만 검색하며
  결과가 많으면 20개씩 나누어 표시한다. 적용 범위는 검색 조건에 맞는 전체 상품, 현재 상품과 같은 대표 분류의
  상품, 모든 상품 중에서 선택한다. 현재 보이는 페이지와 관계없이 조건에 맞는 전체 대상을 한 SQL 갱신으로 처리한다.
  상품명·가격·재고·품절·설명·이미지·옵션과 현재 상품 자체는 복사 대상에서 제외한다.

### 옵션

- 선택옵션은 그룹 최대 3개, 그룹당 값 20개, 조합 1,000개까지다. 그룹 이름과 쉼표 구분 값을 입력하고
  **조합 생성**을 누르면 페이지 이동 없이 선택옵션 영역의 조합 표만 갱신된다. 상품 설명과 선택한 이미지,
  같은 조합에 입력한 차액·재고·통보 기준·사용 여부는 유지된다. 오류가 나면 기존 표를 유지하고 해당 영역에 안내한다.
  조합별 차액·재고를 입력하며, 차액은 판매가에 더하는 값이고 합은 0원 이상이어야 한다.
  차액·재고·통보·사용 옆의 **↓**를 누르면 해당 행의 값이나 체크 상태를 아래 모든 조합에 복사한다.
  **상품 저장**을 눌러야 반영된다. 수정 화면을 다시 열면 저장된 조합의 값 목록도 표시되며,
  품절·미사용 옵션의 값도 유지된다. 값을 추가하거나 바꿨으면 조합을 다시 생성한 뒤 저장한다.
- 추가옵션은 처음에 빈 행 하나를 표시하며 **행 추가** 버튼으로 한 행씩 늘린다. 저장된 추가옵션이 있으면
  해당 행들만 표시한다. 그룹명 없이 항목명·가격·재고를 입력하고, 왼쪽 손잡이를 마우스나 터치로 드래그해
  순서를 정한다. 손잡이에서 위아래 방향키로도 이동하며 드래그 중 Esc를 누르면 원래 순서로 돌아간다.
  가격·재고·통보·사용 옆의 **↓**는 현재 표시 순서대로 아래 행에 값 또는 체크 상태를 복사한다.
  휴지통 버튼으로 행을 삭제하고 **상품 저장**을 누르면 순서와 삭제가 함께 반영된다.
  모든 행을 지운 뒤에도 **행 추가**로 다시 입력할 수 있다. 기존 옵션의 그룹과 ID는 그대로 보존한다.
- 상품 상세에서는 최대 3개의 옵션 선택창을 처음부터 모두 보여 주고, 상위 옵션을 선택하면 다음 선택창을 활성화한다.
  단계 번호와 합산 재고는 표시하지 않으며 마지막 옵션에 해당 조합의 재고와 차액을 표시한다.
  재고가 없거나 사용을 끈 조합은 선택할 수 없고, 상위 선택을 바꾸면 하위 선택이 초기화되며 선택 순서에 따라 비활성화된다.
  마지막 옵션을 선택할 때마다 구매 목록 맨 위에 조합을 추가한다. 예를 들어 화이트를 선택한 뒤 S와 M을 고르면
  화이트/S와 화이트/M을 함께 구매할 수 있다. 조합마다 수량 변경·삭제가 가능하고 전체 금액을 합산한다.
  상위 옵션을 바꿔도 이미 추가한 조합은 유지하며, 같은 조합을 다시 고르면 중복 추가 대신 수량 변경을 안내한다.
  구매수량 제한은 선택한 조합들의 합계에 적용하고, 재고는 조합별로 검사한다.
- 저장은 조합 키 기준으로 갱신하므로 기존 조합의 재고가 유지된다. 제출하지 않은 조합은 삭제된다.
- 재고 변경은 `yc_stock_log`에 남는다. 주문 접수 시 재고가 차감되고, 취소 시 한 번만 복원된다.
- 처리 중인 주문(주문 접수·상품 준비)에 포함된 옵션은 삭제할 수 없다. 판매를 중지하려면 사용 여부를 끈다.

### 이미지

- 상품당 10장. JPG·PNG·WebP·GIF, 8,000px 이하, 용량은 사이트 설정의 첨부 용량을 따른다.
- 파일은 `uploads.dir/youngcart/{상품 id}/`에, 축소본은 `storage/cache/youngcart/`에 저장한다.
- 첫 이미지가 대표 이미지다. 수정 화면에서 순서와 삭제를 지정한다.

## 자동 묶음과 메인 블록

진열 유형 깃발은 없다. 네 묶음은 규칙으로 정해진다: **신상품**은 최근 N일(기본 30) 안에 등록한 상품,
**베스트**는 최근 N일(기본 30) 동안 결제 완료 이후 상태의 주문에서 팔린 수량이 많은 상품, **인기상품**은
누적 조회수가 많은 상품, **할인상품**은 시중가보다 판매가가 낮은 상품이다. 쇼핑몰 설정 → 메인 진열에서
기간과 각 묶음의 사용 여부·진열 크기를 정하고, 묶음마다 **기준**을 "분류 선택"으로 바꾸면 그 분류(하위 포함,
메뉴 숨김 분류 가능)의 상품이 대신 나온다 — 손으로 고른 베스트가 필요할 때 쓴다. 고른 분류를 지우거나
공개에서 내리면 그 묶음은 말없이 자동 규칙으로 돌아간다.

상단 메뉴에는 **메인에 표시**를 켠 묶음만 베스트·신상품·인기상품·할인상품 순서로 놓인다.

메인 화면에는 자동 묶음 아래에 **메인 분류 블록**을 최대 10개 놓을 수 있다. 각 블록은 그 분류와 하위 분류의
상품을 분류의 이미지 크기로 보이고 제목이 분류 페이지로 이어지며, 블록에 정한 **한 행 상품 수 × 행 수**만큼
가져와 그 열 수로 늘어놓는다. 기획전은 메뉴 숨김 분류를 만들어 상품을 넣고 여기에 올리면 된다.
없는 분류를 가리키는 줄과 10개를 넘는 블록은 저장할 때 거절되고(422), 같은 분류를 두 번 올리면 첫 줄만
남는다. 저장한 뒤에 그 분류를 지우거나 공개에서 내리면 그 블록은 메인에서 말없이 빠진다. 보일 상품이 없는
블록은 자동 묶음이든 분류 블록이든 제목째 나오지 않는다.

31판으로 올라갈 때 히트·추천·인기가 켜져 있던 상품은 같은 이름의 메뉴 숨김 분류(`히트상품`, `추천상품`,
`인기상품`)로 옮겨진다. 깃발이 켜진 상품이 하나도 없는 유형은 분류를 만들지 않고, 같은 슬러그를 이미 쓰는
분류가 있으면 `히트상품-2`처럼 번호가 붙는다. 신상품·할인은 규칙이 대신하므로 옮기지 않는다.

## 화면 재정의

테마의 `templates/<테마>/shop/` 아래에 같은 이름의 템플릿을 두면 조각 단위로 재정의된다.
정적 자산은 `www/themes/{테마}/youngcart.css`, `youngcart.js`, `youngcart-admin.css`, `youngcart-admin.js`이며 테마에 없으면 기본 테마 파일을 쓴다.
주문서 주소 검색은 `_postcode.php` 조각과 주문서에서만 읽는 `youngcart-postcode.js`로 재정의한다.
조각의 `data-yc-postcode-*` 요소와 `yc-postcode`, `yc-address`, `yc-address_detail` 입력칸 ID를 유지한다.

- 공개 화면은 GNUCMS 공통 레이아웃 위에 검색·쇼핑 메뉴·카테고리 바로가기·프로모션·상품 그리드를 구성한다.
  쇼핑몰 본문은 공통 `.wrap`의 최대 폭과 좌우 여백을 사용해 사이트 상단 레이아웃과 정렬한다.
  글꼴은 코어의 시스템 글꼴과 본문 14px·행간 1.65를 따르며, 일반 버튼 13px·섹션 제목 19px·페이지 제목 25px를 기준으로 한다.
  모바일 제목은 22px로 줄이고, 배너 제목과 가격은 강조 크기를 따로 둔다. 작은 보조 문구와 버튼의 터치 영역은 유지한다.
  공통 머리글 `_header.php`의 쇼핑 메뉴 오른쪽에 검색 아이콘·주문 조회·장바구니를 표시한다.
  검색 아이콘을 누르면 상품 검색창이 열리며, 자바스크립트가 없어도 열기·닫기와 검색을 사용할 수 있다.
  오늘의집의 쇼핑 탐색 구조를 참고하되 독립적인 코럴 포인트를 사용한다. 기본 테마의 밝기·다크 모드를 따른다.
  홈 프로모션 이미지는 실제 등록된 상품의 이미지를 사용하며, 고정 샘플 상품이나 외부 이미지 요청을 추가하지 않는다.
- 장바구니 `cart.php`, 주문서 `checkout.php`, 주문 조회 `orders.php`, 주문 상세 `order.php`와
  `_feedback.php`, `_steps.php`, `_totals.php`, `_order_detail.php`를 조각 단위로 바꿀 수 있다.
  장바구니의 구매 행은 `_cart_item.php`, 주문서·주문 상세의 상품 묶음과 행은 `_order_products.php`·`_order_product_line.php`를 공유한다.
- `admin/extension.php`는 GNUCMS 공통 관리자 레이아웃·다크 모드·확장 CSS를 유지하면서
  쇼핑몰 CSS와 관리자 전용 CSS·JS를 한 번씩 추가한다. 전용 스타일은 `.yc-admin-page` 안에만 적용한다.
  재정의한 레이아웃에도 이 클래스와 자산을 반영한다. 별도 프런트엔드 빌드는 필요하지 않다.
- 관리자 머리글 `admin/_extension_header.php`, 메뉴 `admin/_nav.php`, 구역 이동 `admin/_form_nav.php`,
  고정 저장 영역 `admin/_save_bar.php`를 재정의할 수 있다. 저장 버튼은 반드시 해당 폼 안에 두거나
  HTML `form` 속성으로 연결한다. 상품 목록의 선택 삭제와 분류 행의 삭제 버튼도 각각 별도의 POST 폼에 연결된다.
  저장된 상품의 하단 고정 저장 영역에는 **상품 보기**가 표시되며 공개 상품 페이지를 새 창으로 연다.
- 관리자 선택옵션 표 `admin/_option_combinations.php`는 최초 표시와 AJAX 조합 생성 응답이 함께 사용한다.
  상품 폼을 재정의할 때 `data-yc-combine`, `data-yc-combinations`, `data-yc-combine-status`를 유지하면
  같은 자리에서 표가 갱신된다. 이 요소가 없거나 자바스크립트를 끄면 기존 폼 제출 방식으로 동작한다.
- 추가옵션 행은 `admin/_extra_option_row.php`를 재정의한다. `template[data-yc-extra-row]`는 모든 행을 삭제한 뒤
  새 행을 만드는 데 사용하고, `data-yc-remove-extra` 버튼은 해당 행을 폼에서 제거한다.
  `data-yc-extra-drag`는 정렬 손잡이이며 이동·삭제 후 입력 이름의 행 번호를 다시 매겨 표시 순서대로 저장한다.
  상품 폼에서만 로컬 `www/vendor/sortablejs/Sortable-1.15.7.min.js`를 관리자 JS보다 먼저 로드한다.
  SortableJS(MIT)의 이동 애니메이션·터치 정렬·자동 스크롤을 사용하며 운영 서버의 설치·빌드는 필요 없다.
  방향키 정렬도 지원하고, 이동 애니메이션은 사용자의 동작 줄이기 설정을 따른다.
  기존 그룹을 담은 숨김 입력 `extras[n][value1]`은 유지하고 새 항목에는 빈 값을 쓴다.
- 추가 구성 수량은 `− 수량 +`로 조절하며 0부터 재고 한도까지 선택한다. 품절 항목은 조절할 수 없다.
  `data-yc-quantity-controls`와 `data-yc-quantity-minus`·`data-yc-quantity-plus`는 장바구니와 같은 수량 처리 코드를 쓴다.
  자바스크립트가 꺼져 있으면 버튼을 숨기고 숫자 직접 입력을 유지한다.
- `_options.php`의 구매 폼은 `product_id`, `selections[선택옵션 ID]`(조합별 수량),
  `extras[추가옵션 ID]`(추가 구성 수량), `action=cart|buy`, `csrf_token`을 `/shop/cart/add`로 POST한다.
  여러 조합을 한 번에 검증하고 장바구니 또는 바로 주문서에 담으며, 하나라도 유효하지 않으면 기존 세션 내용을 유지한다.
  기본 테마는 이 POST를 AJAX로 보내며 성공한 경우에만 장바구니/주문서로 이동한다. 별도 사전 조회 결과를 믿지 않고
  실제 담기 요청에서 최신 재고를 검증한다. 실패하면 상품 화면에서 선택·수량을 유지하고 옵션명과 현재 재고,
  기존 장바구니 수량을 고려한 추가 가능 수량을 안내한다. 수량을 자동으로 줄이거나 일부 항목만 담지 않는다.
  `data-yc-purchase-feedback`·`data-yc-purchase-errors`가 없는 재정의 테마나 자바스크립트를 끈 환경에서는 기존 폼 제출을 유지한다.
  요청 중 중복 제출을 막으며 통신 결과를 확인하지 못했을 때는 자동 재시도하지 않고 장바구니 확인을 안내한다.
  장바구니는 재고를 예약하지 않는다. 주문 접수 시에도 최신 재고를 재검증하고 조건부 갱신으로 차감한다.
  기존 `option_id`와 `quantity` 방식도 지원한다. 옵션 없는 상품은 `option_id=0`을 사용하고,
  자바스크립트가 없거나 기존 테마 조각을 사용하면 전체 조합 선택창에서 하나씩 장바구니에 담을 수 있다.
  기본 JS의 단계별 선택에는 `data-yc-option-*` 요소들과 `options_json.select.items`의 `id`, `v`, `price`, `stock`을 사용한다.
  여러 조합의 구매 목록에는 `data-yc-selections`, `data-yc-selection-template`, `data-yc-single-quantity`와
  구매 폼의 `data-buy-max`를 사용한다. 단계별 필드 `option_step[]`는 화면용이며,
  서버는 제출된 각 선택옵션 ID로 상품 소속·판매 상태·현재 재고·금액을 다시 확인한다.
  재정의한 조각에 단계별 요소가 없으면 기존 조합 선택창을 유지한다. 별도 AI 전용 API 없이도
  각 단계 이름이 붙은 표준 HTML `select`와 `option`의 `disabled` 속성으로 브라우저 자동화를 사용할 수 있다.
- 관리자 상품 목록·상품 재고·옵션 재고 폼에는 `rows[ID][original_stock]` 숨김 필드가 필요하다.
  화면 조회 당시 재고를 보내며, 주문 또는 다른 작업으로 재고가 바뀌었으면 저장을 거절한다.
  주문 내역이 있는 상품은 삭제할 수 없으므로 판매 여부를 끈다.

### 관리자 화면 사용

#### 메인 배너 편집

- **쇼핑몰 → 설정 → 메인 배너** (`/admin/shop/settings#settings-banner`)에서 표시 여부, 상단 문구,
  제목·설명, 버튼 문구·이동 주소를 저장한다. 제목과 설명에는 줄바꿈을 사용할 수 있고 HTML은 문자 그대로 표시한다.
  버튼 문구를 비우면 버튼을 숨긴다. 배너를 꺼도 상품 목록과 신상품·할인상품 안내 타일은 각각의 표시 설정을 따른다.
- 오른쪽 이미지는 네 가지 방식 중 하나를 선택한다.
  - **자동 표시**: 사용 중인 자동 묶음(신상품·베스트·인기·할인 순서)과 분류 블록을 차례로 보고 첫 상품의
    대표 이미지와 이름을 표시한다.
  - **랜덤 표시**: 페이지를 열거나 새로고침할 때마다 현재 메인 화면의 자동 묶음·분류 블록에 진열된 상품 중
    대표 이미지가 있는 상품 하나를 고른다. 여러 블록에 함께 진열된 상품도 후보에 한 번만 포함하며, 비공개
    상품·비공개 대표 분류·꺼져 있거나 상품이 없는 블록과 이미지 없는 상품은 제외한다.
    같은 상품이 연속으로 나올 수 있다. 후보가 없으면 기본 아이콘을 표시한다. 화면을 열어 둔 동안 자동 순환하지는 않는다.
  - **특정 상품 선택**: 대표 이미지가 있는 공개 상품을 고른다. 상품명·이미지 변경도 반영된다.
    나중에 상품이나 대표 분류가 비공개가 되거나 상품·이미지가 삭제되면 해당 카드 대신 기본 아이콘을 표시한다.
  - **직접 업로드**: 이미지 한 장, 대체 설명, 이미지 아래 문구와 클릭 주소를 지정한다.
    JPG·PNG·WebP·GIF, 가로·세로 8,000px 이하이며 용량 제한은 사이트 첨부 설정을 따른다. 정사각형을 권장한다.
- 버튼 주소를 비우면 자동 표시는 상품이 있는 첫 자동 묶음이나 분류 블록의 목록 주소(모든 블록에 상품이
  없으면 첫 메뉴 분류), 특정 상품 선택·랜덤 표시는 표시된 상품 상세로 이동한다.
  랜덤 후보가 없으면 자동 표시와 같은 목록 주소를 사용한다. 직접 입력한 버튼 주소는 모든 방식에서 우선한다.
  업로드 방식도 기본 버튼은 자동 진열 목록을 사용한다. 이미지 클릭 주소를 비우면 링크 없이 표시한다.
  주소는 `/shop/search` 같은 사이트 내 경로, `#앵커`, `http://`·`https://` 주소를 허용한다.
  `/` 경로는 GNUCMS 설치 기준이므로 하위 디렉터리 설치 시 설치 경로를 제외하고 입력한다.
- 새 파일을 선택하면 기존 파일을 교체한다. 저장 실패 시 기존 설정·이미지를 유지하고 새 파일은 정리한다.
  오류를 수정한 뒤에는 업로드할 파일을 다시 선택한다. 저장된 이미지 삭제 시 업로드 방식이었다면 자동 표시로 전환한다.
  다른 표시 방식으로만 전환하면 업로드 파일은 유지해 다시 사용할 수 있다.
- 기존 설치는 현재 문구와 자동 상품 표시를 기본값으로 사용한다. DB 구조 변경이나 별도 마이그레이션은 없다.
  설정은 기존 `yc_settings`에, 업로드는 `uploads/youngcart/0/`에 저장되어 전체 백업에 포함된다.
  `/shop/banner-image?f=파일명`은 현재 저장된 파일만 제공한다. 비표시 상태나 다른 이미지 방식일 때는 관리자만 조회할 수 있다.
- 기본 공개 테마는 `_banner.php`, 관리자 폼은 `admin/_banner_settings.php`를 사용한다.
  테마의 `templates/<테마>/shop/`에서 두 조각을 재정의할 수 있다. 기존 `index.php` 재정의에는
  새 `banner` 뷰 데이터와 `_banner` 삽입을 반영해야 설정이 표시된다.
  기존 설정 폼에 배너 필드가 없으면 저장된 배너를 보존한다. 업로드를 사용하는 재정의 폼에는
  `enctype="multipart/form-data"`와 `banner_image` 파일 입력이 필요하다.

#### 운영 화면

- 현황에는 상품 설정별 수량, 전체 기간의 현재 주문 상태, 최근 주문 최대 5건과 재고 통보 기준 이하의
  상품·옵션 최대 6건을 표시한다. 주문 수를 누르면 해당 상태의 주문 목록으로 이동한다.
- 상품 목록에서는 상품명·가격·재고·판매 상태를 편집하고 **목록 변경사항 저장**을 누른다.
  저장은 현재 페이지의 모든 입력에 적용되고, 체크박스는 **선택 삭제**와 분류 넣기·빼기에 쓰인다.
  분류 삭제는 각 행에서 처리한다. 목록 아래 **기존 상품으로 새 상품 만들기**에서 복사 내용을 불러오면 새 상품 등록
  화면에 상품 정보·옵션·이미지가 채워지며, 이때는 아직 상품이 생성되지 않는다. 내용을 확인하고 **새 상품 저장**을
  눌러야 이미지와 상세 설명 사진을 포함한 새 상품이 등록된다.
- 상품·분류 등록과 설정에는 구역별 바로가기와 하단 고정 저장 버튼이 있다. 상품 여분필드와 분류 HTML은
  펼쳐서 입력한다. 자바스크립트 없이도 구역 이동·펼치기·저장이 가능하다.
  자바스크립트를 사용할 때는 미저장 변경 안내, 선택 개수, 오류 입력칸 안내를 추가한다.
- 관리자 주문 목록은 주문자·받는 분을 한 줄에, 첫 상품명과 나머지 상품 종류 수(`외 n개`)를 다음 줄에 표시한다.
  긴 상품명은 칸 너비에 맞춰 줄인다.
  새 주문번호는 사이트 시간대의 주문일 6자리(`yymmdd`)와 무작위 숫자 7자리를 하이픈으로 연결해 발급한다(예: `261001-0483920`).
  뒤 숫자는 앞의 `0`을 포함해 항상 7자리이며, 중복이면 새 번호로 다시 시도한다. 기존 주문번호는 그대로 유지하고 주문일시는 번호 아래 줄에 표시한다.
  상태 메뉴는 입력한 검색어를 유지한다. 주문 상세에서는 고객·배송 정보, 금액, 처리 이력을 함께 확인한다.
- 모바일에서 주문 목록은 카드형으로, 편집할 열이 많은 상품·분류·재고 표는 내부 가로 스크롤로 표시한다.

## 장바구니와 주문

- 장바구니는 브라우저의 GNUCMS 세션에 저장되며 기기 간 동기화하지 않는다. 세션이 끝나면 장바구니도 사라진다.
  상품·옵션 ID와 수량만 저장하고 가격·옵션 차액·판매 상태·재고를 서버에서 다시 조회한다.
- 선택옵션이 다르면 별도 구매 항목으로 세고, 추가옵션은 같은 상품 아래 **추가 구성**으로 묶는다.
  같은 상품의 여러 선택옵션을 함께 담으면 추가 구성은 공통으로 한 번 표시한다. 상품 사진·이름은 추가 구성에 반복하지 않는다.
  상단 장바구니 배지는 옵션과 수량에 관계없이 상품 종류 수를 표시한다. 추가 구성도 같은 상품 종류로 묶되 금액·재고는 계산한다. 주문서와 주문 상세도 같은 구조다.
  주문 상세는 현재 진행 상태와 그 상태로 변경된 시각을 상단에 표시하고, 전체 진행 이력은 상품·배송·결제 정보 아래에 표시한다.
  추가 구성만 삭제하거나 수량을 0으로 저장할 수 있으며, 같은 상품의 마지막 본상품·선택옵션을 지우면 추가 구성도 함께 지운다.
- 상품 수량은 최대 9,999개, 장바구니의 처리 항목(추가 구성 포함)은 최대 100개다. 상품별 최소·최대 구매수량은 모든
  선택옵션의 본품 수량을 합산해 검증한다. 최소수량은 주문 시 검사하며 추가옵션은 본품 없이 주문할 수 없다.
- 장바구니에서도 상품 상세와 같은 **− · 수량 · +** 버튼 또는 직접 입력으로 수량을 바꾸고
  **수량 변경 저장**을 누른다. 저장 후 금액·배송비를 다시 계산하며, 상품 제거는 삭제 버튼을 사용한다.
  본품을 모두 지우면 해당 상품의 추가옵션도 제거된다.
- **바로 주문하기**는 별도 주문서를 열며 기존 장바구니는 유지한다.
- 주문서와 주문 조회는 회원만 사용할 수 있다. 로그인하지 않았다면 로그인 화면을 거쳐 원래 주문서로 돌아온다.
  주문자명은 공개 닉네임과 분리한 회원정보(`users.buyer_name`)를 쓰고 휴대폰은 기존 `users.phone`을 사용한다.
  회원정보 수정과 관리자 회원 수정에서 주문자명·휴대폰을 입력한다. 회원정보의 휴대폰 칸은 가입 시 수집 여부와 무관하게 제공한다.
  주문서는 저장된 주문자 정보를 요약으로 표시하고 없는 이름·휴대폰만 입력받는다. 닉네임이나 이전 주문의 이름을 실제 주문자명으로 자동 저장하지 않는다.
  최초 입력은 주문 접수가 성공했을 때 주문·재고와 같은 트랜잭션에서 미등록 회원정보만 채운다. PG 주문은 승인 전 암호화된 주문서에 저장 여부를 보존하고 승인 후 주문 생성 시 반영한다. 동시 수정된 기존 회원정보는 덮어쓰지 않는다.
  이전 배송지 선택과 새 배송지는 받는 분·연락처·주소·배송 요청만 변경한다. 주문자 정보를 변경하려면 회원정보를 수정한다.
  회원 이메일이 유효하면 자동 적용하고, 소셜 임시 이메일인 경우만 해당 주문에서 사용할 이메일을 입력받는다. 이메일 인증 정보는 변경하지 않는다.
  소셜 로그인의 내부용 임시 이메일은 주문서 이메일을 비워 둔다.
  주문자 휴대폰은 회원정보의 번호를 자동 적용하며, 없는 경우만 주문서에서 입력한다. “주문자 정보와 동일” 버튼은 주문자 이름과 연락처를 받는 분 이름과 연락처에 복사한다.
  받는 분·연락처·우편번호(국내 5자리)·주소를 입력하고, 상세주소·배송 요청사항은 선택한다.
  이전 주문의 배송지 중 기본 배송지(없으면 최근 배송지)를 미리 채우거나 다른 이전 배송지를 선택할 수 있다.
  새 주문의 배송지·배송 요청사항을 기본값으로 저장할 수도 있다.
- 우편번호 오른쪽의 **주소 검색**은 [카카오 우편번호 서비스](https://postcode.map.kakao.com/guide)를 사용한다.
  API 키 없이 사용할 수 있으며 버튼을 누를 때 공식 CDN의 `postcode.v2.js`를 읽고 주문서 안에 검색창을 표시한다.
  선택한 도로명·지번 주소와 5자리 우편번호를 채우고 상세주소로 이동한다. 다른 주소를 고르면 기존 상세주소는 비운다.
  검색 취소 시 입력 내용은 유지하며, 서비스 연결 실패·자바스크립트 미사용 시에도 주소를 직접 입력할 수 있다.
- 주문 내용과 배송 정보 제공을 확인한 후 **주문하고 결제하기**를 누른다. 카드는 주문서에서 결제창이 열리고,
  무통장은 입금 안내를 표시한다. 결제 수단이 없으면 **주문 접수**만 한다.
  카드 승인이 확인돼야 주문·재고 차감이 발생한다. 같은 주문서를 여러 번 제출해도 주문과 재고 차감은 한 번만 발생한다.
- 주문서를 연 뒤 상품·옵션·배송비·주문 안내가 바뀌면 최신 내용을 다시 확인하도록 안내한다.
  주문 접수 시 상품·옵션 재고를 하나의 트랜잭션에서 차감하므로 일부 상품만 접수되지 않는다.
  재고 차감은 예약 성격이며 주문 접수 자체가 입금 확인을 의미하지 않는다.
- 접수된 주문은 DB에 저장되므로 장바구니 세션이 끝나도 남는다. 회원은 로그인 후 자신의 주문을 조회한다.
  주문 조회 목록에는 사이트 시간대 기준으로 주문일시를 초까지 표시하고 한글 요일을 붙인다(예: `26-10-01 14:35:27 (목)`).
  주문 접수 시도는 일반 이용자 기준 10분에 20회로 제한한다.
- 구매자는 **주문 접수·결제 완료** 상태에서 상품 준비 전까지 주문 전체를 취소할 수 있다. 카드 결제 완료 주문은 결제사 전액 취소 후 주문을 취소하며, 취소는 재고를 한 번만 복원한다.
  무통장입금 완료 주문은 주문을 취소한 뒤 관리자가 송금액을 반환하고 취소된 주문에 환불 내역을 기록한다.
  관리자는 결제 완료·상품 준비 상태에서 부분·전액 환불을 처리한다. 무통장은 실제 송금 후 환불 기록만
  남긴다. 전액 환불과 함께 취소하면 재고가 복원된다. 상품별 부분 취소와 주문 내용 변경은 지원하지 않는다.

### 배송비 계산

| 배송 유형 | 계산 |
|---|---|
| 상점 기본 | 같은 선불/착불 방식의 기본배송 상품을 묶어 기본 배송비를 한 번 적용. 해당 묶음의 상품·옵션 금액 합계로 무료 기준을 검사 |
| 무료 | 0원 |
| 조건부 무료 | 해당 상품의 선택·추가옵션 포함 금액 합계가 무료 기준 이상이면 0원, 아니면 지정 배송비 |
| 유료 | 해당 상품에 배송비 한 번 적용 |
| 수량별 | 본품 수량을 지정 수량으로 나눈 뒤 올림한 횟수 × 배송비. 추가옵션 수량은 제외 |

기본 배송비와 무료 기준의 초기값은 0이다. 무료 기준 0은 금액에 따른 무료배송을 적용하지 않는다.
선불은 주문 금액에 포함하고, 착불은 수령 시 별도 금액으로 표시한다. 상품이 선불·착불 선택을
허용하면 주문서에서 선택한 뒤 **배송비 반영하기**를 누른다. 도서산간 추가비·해외 배송은 지원하지 않는다.

### 관리자 주문 처리

`/admin/shop/orders`에서 상태별 또는 주문번호·주문자 검색으로 찾고 상세 화면에서 처리한다.
주문 현황 카드에서도 해당 상태 목록으로 바로 이동할 수 있다.

| 현재 상태 | 다음 상태 | 관리자 되돌리기 |
|---|---|---|
| 주문 접수 | 입금 확인 또는 PG 승인으로 결제 완료, 주문 취소 | 없음 |
| 결제 완료 | 배송 중(운송장 등록), 상품 준비(선택), 전액 환불 후 주문 취소 | 무통장입금·접수 전용 주문은 주문 접수로 되돌림 |
| 상품 준비 | 배송 중(택배사·운송장 필수), 전액 환불 후 주문 취소 | 결제 완료로 되돌림 |
| 배송 중 | 배송 완료, 전체 반품 요청 | 직전 준비 상태로 되돌리고 택배사·운송장 번호 제거 |
| 배송 완료 | 전체 반품 요청 | 배송 중으로 되돌리고 판매수량 차감 |
| 반품 요청 | 상품 회수 후 반품 완료·잔액 환불, 환불 전 요청 종료 | 없음 |
| 반품 완료 | 없음 | 없음 |
| 주문 취소 | 없음 | 없음 |

주문 상세에 기본 택배사의 운송장 번호가 있으면 택배사명과 번호를 공식 배송조회 링크로 표시한다.
CJ대한통운·한진·로젠·경동은 번호가 조회 주소로 전달되며, 롯데·우체국은 공식 조회 화면에서 번호를 입력한다.
목록에 없는 택배사는 운송장 정보를 텍스트로 표시한다.

이력에는 처리자·시각·상태·관리자 메모가 남는다. 관리자 메모는 구매자에게 공개하지 않는다.
처리 이력의 각 상태 일시 옆 `+`를 누르면 해당 상태와 다음 상태 사이에 관리자 메모를
넣을 수 있다. 마지막 상태 뒤에도 추가할 수 있다. 메모에는 실제 작성 시각을 표시하고,
수정·삭제는 관리자만 할 수 있다. 메모 저장과 주문 상태 변경 뒤에는 변경된 처리 이력으로 이동한다.
처리 이력에서 현재 상태를 기록한 행의 `이 상태 되돌리기`를 누르면 사유 입력 창이 열린다. 이전 상태는
그 뒤의 상태를 먼저 되돌린 다음 정정할 수 있다. 되돌린 사유와 결과는 이력에 남는다. 카드 결제 승인과
실제 배송·PG 환불은 상태 되돌리기로 취소되지 않는다. 결제 완료를 주문 접수로 되돌리는 기능은
PG 주문과 이미 환불된 주문에는 제공하지 않는다.
배송 완료 때 본품의 판매수량이 증가한다. 자동 무통장 입금 확인과 주문 이메일·문자 발송은
아직 없으므로 접수 주문을 관리자가 주기적으로 확인해야 한다. 결제 기한이 지난 미결제 주문은
관리자 주문 화면·주문 접수 시 자동 취소되며, 승인 중인 PG 주문은 별도 확인이 필요하다.
접수 대기 주문은 취소할 때까지 재고를 점유한다. 장바구니에 담는 시점에는 재고를 점유하지 않는다.

실제 개발 사이트의 샘플 등록·주문·입금·배송·취소·환불 검증 결과와 이미지 출처는
[2026-09-22 검증 기록](shop-e2e-20260922.md)에 정리했다. 실제 PG 승인 검증과 모의 응답 테스트를 구분한다.

## 배송 요청사항 선택

주문서의 배송 요청사항은 문 앞, 부재 시 경비실, 부재 시 택배함, 배송 전 연락, 부재 시 연락과 직접 입력을 제공한다. 선택한 문구와 직접 입력은 기존 `delivery_note`로 제출하며 DB 구조는 변경하지 않는다. 저장된 이전 배송지 문구는 해당 선택지나 직접 입력으로 복원하고, 입력 오류·배송비 재계산에서도 보존한다. JavaScript를 사용할 수 없는 경우 직접 입력란을 표시한다.

## 관리자 상단 메뉴

쇼핑몰 관리 메뉴는 운영 현황 → 주문 → 배송 → 정산 → 상품 → 분류 → 설정 순서다. 배송은 상품 준비 주문 선택, 피킹·포장 인쇄와 택배 CSV 출력, 운송장 일괄 등록을 담당한다. 주문별 상태 변경은 주문 목록·상세에서 처리한다. 정산 아래에는 매출 리포트, 정산 대사, 결제 오류를 표시한다. 정산 첫 화면은 매출 리포트이며 기존 각 화면 URL과 접근 권한은 유지한다. 좁은 화면에서는 상단 메뉴를 줄바꿈한다.

## 1인 운영을 위한 기본 흐름

상품명·가격·판매할 수량·과세/면세·분류와 사진·설명을 등록한다. 상품 코드는 비워 두면 자동 생성한다. 과세/면세는 운영자가 선택하며 상품 종류만으로 세금 설정을 자동 변경하지 않는다. 상품정보고시는 유지한다. 상품별 배송비·옵션·구매 제한·추가 분류 등 예외만 접힌 추가 설정에서 수정하며, 기존 입력과 설정은 보존한다.

상품 재고와 옵션 재고의 첫 화면은 **재고 보충**이다. 수확·입고한 수량만 현재 수량에 더한다. 입력하지 않은 행은 변경하지 않고 묶음 전체를 한 거래로 처리한다. 수량과 처리 일시는 기존 재고 로그에 자동 기록한다. 상품 잠금과 보충 요청 키로 주문 차감의 덮어쓰기와 동일 요청의 재보충을 막는다. 최근 이력은 20건을 표시한다. 실사 수량 정정과 판매 설정은 **수량 조정·판매 설정**에서 기존 수정 경로를 사용한다. 공급처·원가·입고 담당자·입고일 입력은 추가하지 않는다.

주문은 **결제 확인 → 발송 처리 → 배송 완료**가 기본이며 상품 준비는 선택 단계다. 배송 화면은 결제 완료·상품 준비 주문을 모으고 택배사·운송장번호를 입력해 바로 발송할 수 있다. 결제 전에는 발송할 수 없으며 기존 인쇄·CSV 일괄 등록도 유지한다. 결제 완료에서 바로 발송한 주문을 되돌리면 실제 직전 상태인 결제 완료로 돌아간다. 배송 시 재고를 다시 차감하지 않는다.

주문 이메일은 회원정보를 그대로 사용하고 없으면 새 주소를 입력받지 않는다. 주문자와 받는 분이 같으면 체크 한 번으로 이름·전화번호를 재사용하며 다른 받는 분 정보는 따로 입력할 수 있다. 입금자명은 주문자와 다를 때만 입력한다. 배송비의 합계는 주문 요약에, 세부 계산은 접힌 항목에 표시한다. 기존 주문 개인정보는 삭제하지 않으며 보존·파기 정책은 별도로 정한다.

주문 전체 반품은 배송 중·배송 완료 주문에서 사유만 입력해 요청한다. 관리자는 주문 목록의 반품 요청 검색 또는 주문 상세에서 처리한다. 회수 확인 후 카드 결제는 기존 결제사 취소 경로로 남은 결제액을 환불하고, 무통장입금은 실제 반환 완료 확인 후 기록한다. 반품 완료는 판매수량을 조정하고 재고 복원 선택 시에만 상품·옵션 재고를 복원한다. 같은 완료 요청을 다시 받아도 환불·재고·알림을 반복하지 않는다. 요청 취소·종료는 환불이 진행되지 않은 경우에만 원래 배송 상태로 복귀한다. 반품 요청·완료와 종료의 알림함은 필수이며 종료는 메일만 선택한다. 반품 완료의 환불 기록은 알림함에 남기되 외부 환불 안내는 반품 완료 안내에 묶어 중복 발송하지 않는다. 승인 알림톡 연결 전에는 공통 설정의 문자 대체 규칙을 따른다. 별도 반품 테이블·주소·전화·계좌 수집은 없으며 교환·부분 반품은 지원하지 않는다.

환불 처리 시작을 주문 결제 상세에 기록한 뒤 PG 원장을 별도 거래로 확정한다. 통신 응답이 유실되어도 원장이 롤백되지 않으며 자동 재전송하지 않는다. 결제사 기록과 대조한 환불도 별도 외부 안내를 보내지 않고 반품 완료 안내에 묶는다.
