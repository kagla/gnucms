## 실제로 실행한 흐름

- 코어·공식 사이트 소스 사본과 완성 배포 ZIP에서 HTTP 설치 마법사, DB 연결, 관리자·설정 생성, 설치기 자동 삭제를 각각 확인했다.
- HTTP 관리자 로그인, 메일 미사용 저장, 게시판·글·댓글 생성, 비회원 관리자 접근 차단을 확인했다.
- HTTP 상품 상세·장바구니·회원 주문·중복 주문 방지·비회원 주문 접근 차단·취소·재고 복원을 확인했다. PG 설정이 없는 접수 전용 주문을 사용했다.
- 실제 DB 덤프와 파일 ZIP 생성·체크섬 검증·다운로드를 수행하고 다른 전용 DB에 SQL을 수동 복원해 작성한 글이 보존되는지 확인했다. 자동 복원 요청은 안내대로 거절됐다.
- 완성 배포 ZIP의 체크섬·CRC·vendor와 KCP Linux 실행 모듈·공개 키 포함 및 사용 가능 상태를 확인했다. 실제 KCP 승인 명령은 실행하지 않았다.
- 공식 사이트의 modern 테마로 전환해 관리·쇼핑몰과 매뉴얼 55개를 포함한 73개 화면의 정상 응답을 확인했다.
- 전체 검사에는 회원 인증·권한·첨부·스키마 갱신·알림·주문·배송·반품·PG별 승인/환불 처리·백업 및 CLI 검사가 포함된다. 외부 결제·발송은 테스트 전송을 사용했다.

## 발견 사항과 조치

- 알리고 결과 조회 테스트가 로컬 시각으로 UTC 필드를 만들던 문제를 Clock 기반 UTC로 수정했다.
- 화면 날짜 검사에 기대하는 시간대를 명시해 서버 기본 시간대에 따른 실패를 없앴다. 사이트 시간대 변환 검사는 그대로 유지했다.
- 공식 사이트의 예전 메뉴·버튼 문구 기대값을 현재 알림·발송 경로와 공개 링크 계약에 맞췄다.
- 처음 낮게 설정한 시험 DB 연결 한도 때문에 발생한 환경 오류를 해소하고 전체 검사를 다시 실행했다. 운영 DB 설정은 변경하지 않았다.
- 수동 CI에 PHP 8.2·8.4 검사와 실제 HTTP 설치·수동 복원 회귀 검사를 추가했다. 일반 push로 자동 테스트나 릴리스를 실행하지 않는다.

운영본·저장소 대조에서 개발 사이트와 공식 사이트 GitHub의 태그 없는 편집기 본문이 `&middot;` 등을 중복 이스케이프하는 문제를 재현했다. 코어 0.9.6에 이미 있는 수정을 개발 사이트 운영본과 공식 사이트 저장소의 운영·기본 브랜치에 맞췄다. 공식 사이트 운영본에는 이미 같은 수정이 적용돼 있어 보존했다. 수정 후 가운데점·숫자 문자 참조·저작권 기호와 문자 코드 설명문을 보존하고, 인코딩된 스크립트가 실행 태그로 바뀌지 않는지 확인했다. 기존 저장 데이터를 일괄 치환하지 않았다.

선택 실행 옵션을 추가할 때 생긴 CI 들여쓰기 오류도 고쳤으며, 수정된 설정으로 두 PHP 버전의 회귀 검사와 HTTP 설치 검사가 통과했다. 테스트에서 생성한 DB·계정과 임시 MariaDB 프로세스는 정리했다.

## 검증 한계

실제 카드 승인·청구·외부 PG 관리자 취소, 문자/알림톡 실수신과 과금, 외부 메일 수신·OAuth 사업자 실제 로그인, 고객 호스팅에 대한 FTP/SFTP 원격 설치는 실행하지 않았다. 대체 전송 검사의 통과는 외부 사업자 계약·호스팅 정책·네트워크·수신 성공의 보장이 아니다. 확인한 PHP/DB 조합과 다른 모든 버전의 검증으로 확대 해석하지 않는다.
